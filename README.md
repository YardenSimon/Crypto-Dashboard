# Cryptide — Personalised Crypto Dashboard

A full-stack cryptocurrency dashboard that surfaces real-time prices, curated news, AI-generated market insights, and community memes — all filtered to each user's personalised watchlist and investor profile.

**Live demo:** [cryptide.vercel.app](https://cryptide.vercel.app) &nbsp;·&nbsp; **API:** [cryptide-api.up.railway.app](https://cryptide-api.up.railway.app/health)

> Screenshots coming after first production deploy.

---

## Features

- **Personalised onboarding** — multi-step quiz lets users pick their coins (BTC, ETH, SOL, and 9 more), investor archetype (HODLer / Day Trader / NFT Collector), and content preferences
- **Live prices** — real-time coin prices, 24 h change, and market cap via CoinGecko
- **Crypto news** — aggregated from Cointelegraph, Decrypt, and CoinDesk RSS feeds, auto-tagged by coin
- **AI insights** — daily investment takes generated by Groq (with Gemini as fallback), tailored per investor type; users can force-regenerate with a 1-hour rate limit
- **Reddit memes** — daily meme pulled from r/cryptocurrencymemes
- **Voting** — upvote / downvote any piece of content; scores persist per user
- **Drag-and-drop layout** — long-press any dashboard card to reorder columns; layout saved server-side
- **Session auth** — HttpOnly JWT cookie with Argon2-hashed passwords

## Local Setup

### Prerequisites

- [Docker Desktop](https://www.docker.com/products/docker-desktop/)
- Node.js 20+ (only needed if you want to run the frontend outside Docker)

### 1. Clone & configure environment

```bash
git clone https://github.com/<your-username>/Crypto-Dashboard.git
cd Crypto-Dashboard
cp .env.example .env          # edit .env and fill in your API keys (see table below)
cp web/.env.example web/.env  # sets VITE_API_BASE_URL=http://localhost:8000
```

### 2. Start all services

```bash
docker-compose up
```

This starts:
- **postgres** on port 5432 (with a persistent volume)
- **api** on [http://localhost:8000](http://localhost:8000) — runs `alembic upgrade head` then uvicorn
- **web** on [http://localhost:5173](http://localhost:5173) — Vite dev server with hot reload

### 3. Open the app

Navigate to [http://localhost:5173](http://localhost:5173), sign up, and complete the onboarding quiz.

## Environment Variables

### Backend (`api/` — `.env` or Railway Variables)

| Variable | Required | Description |
|---|---|---|
| `DATABASE_URL` | Yes | PostgreSQL connection string (Docker default: `postgresql://cryptide:cryptide@postgres:5432/cryptide`) |
| `JWT_SECRET` | Yes | 32+ random bytes used to sign auth tokens. Generate with `openssl rand -hex 32` |
| `JWT_ALGORITHM` | Yes | Signing algorithm — use `HS256` |
| `ENVIRONMENT` | Yes | `development` or `production`. Controls cookie security flags and CORS |
| `FRONTEND_ORIGIN` | Yes | Allowed CORS origin, e.g. `http://localhost:5173` locally or your Vercel URL in prod |
| `GROQ_API_KEY` | Yes | Powers AI insights (primary LLM). Get one at [console.groq.com](https://console.groq.com) |
| `GEMINI_API_KEY` | Yes | Fallback LLM for AI insights. Get one at [aistudio.google.com](https://aistudio.google.com) |
| `COINGECKO_API_KEY` | No | Increases CoinGecko rate limits. Free key available at [coingecko.com](https://www.coingecko.com/en/api) |
| `CRYPTOPANIC_API_KEY` | No | Reserved for future news expansion |

### Frontend (`web/` — `web/.env` or Vercel Variables)

| Variable | Required | Description |
|---|---|---|
| `VITE_API_BASE_URL` | Yes | Base URL of the API, no trailing slash (e.g. `http://localhost:8000` or your Railway URL) |

## Deployment

### Backend → Railway

1. Create a new Railway project and add a **PostgreSQL** database service.
2. Add a second service from your GitHub repo with **Root Directory** set to `api/`.
3. Set the environment variables below on the API service:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` (Railway reference variable) |
   | `JWT_SECRET` | Output of `openssl rand -hex 32` |
   | `JWT_ALGORITHM` | `HS256` |
   | `ENVIRONMENT` | `production` |
   | `FRONTEND_ORIGIN` | *(fill in after Vercel deploy)* |
   | `GROQ_API_KEY` | your key |
   | `GEMINI_API_KEY` | your key |

4. Deploy and confirm the **Logs** tab shows `alembic upgrade head` completing and uvicorn starting.
5. Generate a public domain in **Settings → Networking** and note the URL.

### Frontend → Vercel

1. Import the same GitHub repo in Vercel with **Root Directory** set to `web/`.
2. Set `VITE_API_BASE_URL` to the Railway URL from above.
3. Deploy and note the Vercel URL.

### Wire CORS

Back in Railway, set `FRONTEND_ORIGIN` to the Vercel URL and redeploy.

### Post-deploy checklist

- [ ] `/health` returns `{"status": "ok"}`
- [ ] Sign up → onboarding → dashboard loads correctly
- [ ] DevTools → Application → Cookies → `access_token` is `Secure; SameSite=None; HttpOnly`
- [ ] Refresh `/dashboard` directly → no 404
- [ ] Logout → redirects to `/login`

## API Reference

| Method | Path | Auth | Description |
|---|---|---|---|
| `GET` | `/health` | — | Health check |
| `POST` | `/auth/signup` | — | Register, returns user + sets cookie |
| `POST` | `/auth/login` | — | Login, sets cookie |
| `POST` | `/auth/logout` | Cookie | Clear cookie |
| `GET` | `/me` | Cookie | Current user info |
| `GET` | `/me/preferences` | Cookie | User preferences |
| `PUT` | `/me/preferences` | Cookie | Update preferences |
| `PATCH` | `/me/layout` | Cookie | Save column layout |
| `PATCH` | `/me/coin-order` | Cookie | Save coin order |
| `GET` | `/dashboard` | Cookie | Aggregated dashboard data |
| `POST` | `/insights/retry` | Cookie | Regenerate insights (1 h rate limit) |
| `POST` | `/votes` | Cookie | Cast or clear a vote |
